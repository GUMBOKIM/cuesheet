# `?cue=` 링크

[English](./cue-links.md) | **한국어** · [전체 문서](./index.ko.md)

`?cue=` 값은 cuesheet 상태 전체를 담은 문자열 하나입니다. 이 값을 붙여 열면 앱이 그 상태로 시작합니다.
누군가에게 화면을 넘길 때도, 테스트를 특정 상태에서 시작할 때도 이게 제일 간단합니다. 이 페이지에서는
문법, 링크가 적용되는 방식, 현재 상태 공유, 링크로 재현되는 것과 안 되는 것을 다룹니다.

```text
/?cue=getCoupons:Empty,delay:800
```

## 문법

항목은 쉼표로 구분합니다.

| 항목 | 의미 |
|---|---|
| `getCoupons:Empty` | 핸들러 `getCoupons`의 시나리오 `Empty`를 선택 |
| `delay:800` | 응답하는 모든 요청을 800ms 지연(밀리초 단위 정수) |
| `delay:800-2000` | 800~2000ms 사이의 무작위 지연 |
| `time:2026-01-31T09:00:00Z` | 시계를 그 시각에 고정 |
| `time:2026-01-31T09:00:00Z/running` | 그 시각부터 시계가 흐름 |
| `offline` | 요청이 네트워크 오류처럼 실패. 지연을 걸었다면 그만큼 기다린 뒤 |
| `-getCoupons` | `getCoupons` 핸들러 끄기. 이 API 요청은 실제 서버로 감 |
| `-getCoupons,getCoupons:Empty` | 끄되 `Empty`는 골라 둔 채로 두기 |
| `on` | cuesheet 켜기 |
| `off` | cuesheet 끄기. 요청이 실제 서버로 감 |

- `-getCoupons,getCoupons:Empty`: 핸들러를 다시 켜면 `Empty`로 응답합니다. 두 항목의 순서는
  상관없습니다.
- 고정된 `time:`에서는 lodash `debounce` / `throttle`처럼 `Date.now()`로 기다리는 코드가 멈춥니다.
  그런 화면에는 `/running`을 붙이세요([자세히](./how-it-works.ko.md)).
- `on`: `off` 말고 다른 항목이 하나라도 있으면 자동으로 켜집니다.
- `off`: 기본값에서 시작하되 전체 스위치만 꺼집니다. 핸들러는 전부 켜진 채이고, 같은 링크에 있던 시나리오·
  `delay`·`time`·`offline`은 버려집니다. 다시 켜면 모든 API가 기본값으로 모킹됩니다.

예시:

```text
/?cue=redeemCoupon:Server error,delay:1500
/?cue=time:2026-01-31T23:59:00+09:00/running
/?cue=on                                       모든 설정을 기본값으로
```

## 규칙

### 링크 적용

- **링크가 상태 전체를 정합니다.** 링크에 없는 건 전부 기본값으로 돌아가서, 핸들러는 첫 번째 시나리오로
  응답하고 지연, 시계, 오프라인은 꺼집니다. 이전 링크가 남긴 상태에 기대지 않으니 링크는 항상 같은
  상태를 재현합니다.
- **`off`를 뺀 모든 항목이 cuesheet를 켭니다.** `on`은 "기본값으로 켜기"만 하고 싶을 때 쓰세요.
- **적용하고 나면 주소창에서 `cue`를 지웁니다.** 다른 쿼리 파라미터는 한 글자도 바꾸지 않습니다.
- **새로 고침해도 상태가 남습니다.** 영구 저장소를 쓰면(예: `storage: window.localStorage`) 다른
  걸 바꾸기 전까지 유지됩니다.
- **빈 `?cue=` 값은** 주소창에서 지우기만 하고 아무것도 바꾸지 않습니다. 이걸로 cuesheet를 켤 수는 없습니다.

### 잘못 입력했을 때

- **잘못 입력해도 페이지는 멈추지 않습니다.** 모르는 핸들러나 시나리오, 해석할 수 없는 값은 경고만
  남기고 그 항목만 건너뜁니다. 모르는 시나리오면 경고에 쓸 수 있는 시나리오 목록이 같이 나옵니다.
- **`delay:`에는 밀리초 단위 정수만 씁니다**(`delay:800`, `delay:800-2000`). 그 밖의 값(`delay:-500`,
  `delay:1.5`, 끝이 시작보다 작은 범위)은 경고를 남기고 건너뜁니다.
- **읽을 수 있는 항목이 하나도 없는 링크는 아무것도 바꾸지 않습니다.** 오타, 다른 도구가 붙인 값,
  `off`가 아닌 `?cue=OFF`처럼 모든 항목을 건너뛴 경우에는 "기본값으로 켜기"로 읽어서 저장하는 대신
  경고만 남기고 상태를 그대로 둡니다.

### 값 쓰기

- **시각은 ISO 8601 형식입니다.** 쿼리 문자열에서 `+`가 공백으로 바뀌어도 `T…` 시각 뒤에 붙은
  `+09:00`이나 `+0900` 같은 오프셋은 제대로 동작합니다. 다른 경로로 정한 시각(예: `patch()`에
  `'2026-01-31 09:00'`)도 ISO로 저장하니, 그 공유 링크를 열면 같은 시각이 됩니다.
- **시나리오 이름의 공백**은 브라우저 주소창에 칠 때는 그대로 둬도 됩니다. 코드에서 URL을 만들 때는
  값을 `encodeURIComponent`로 인코딩하세요.
- **핸들러 id와 시나리오 이름은 항상 링크에 담을 수 있습니다.** 담을 수 없는 이름은 인스턴스를 만들 때
  cuesheet가 거부하기 때문입니다. `on`, `off`, `offline`, `delay`, `time`인 id, `-`로 시작하는 id, `,`나
  `:`가 들어간 id, `,`가 들어간 시나리오 이름, 빈 이름, 앞뒤에 공백이 있는 이름이 여기 해당합니다.
  [핸들러 검사](./handlers.ko.md#핸들러-검사)를 참고하세요.
- **시나리오 이름 안의 `:`는 괜찮고**, `+`, `#`, `&`도 인코딩만 하면 괜찮습니다(아래 참고).

> [!WARNING]
> 링크를 손으로 칠 때는 `+`를 `%2B`로, `#`을 `%23`으로, `&`를 `%26`으로 쓰세요. 쿼리 문자열에서 그냥
> `+`는 공백을 뜻하고, `#`은 프래그먼트를, `&`는 다음 파라미터를 시작합니다. Copy URL과 `toShareUrl()`은
> 알아서 인코딩해 줍니다.

## 현재 상태 공유하기

- **패널:** 버튼으로 현재 상태 링크를 복사합니다.
- **`cuesheet.toShareUrl()`:** `?cue=`가 붙은 현재 페이지 URL을 반환합니다.
- **`cuesheet.toShareParam()`:** 값만 반환합니다(`on,getCoupons:Empty,delay:800`).

기본값과 같은 항목은 빼니까 링크가 짧습니다.

## 링크로 재현되는 것과 안 되는 것

링크는 같은 앱, 같은 핸들러 정의에서 **cuesheet의 상태**를 재현합니다. 이런 건 담기지 않습니다.

- **cuesheet 밖의 데이터.** 로그인한 사용자, 앱이 자기 저장소에 둔 값, 핸들러가 없는 API의 응답.
- **범위로 정한 지연의 정확한 값.** 범위만 재현됩니다.
- **cuesheet가 시작되기 전에 읽은 날짜.** 나중에 시각을 바꾸지 말고 처음부터 링크로 페이지를 여세요
  ([테스트](./testing.ko.md#시계) 참고).

> [!NOTE]
> 링크를 여는 사람도 cuesheet가 켜진 빌드여야 합니다(개발 서버, 또는 개발 환경 조건이 cuesheet를
> 들여보내는 QA 빌드. 예: `import.meta.env.DEV || import.meta.env.MODE === 'qa'`).
